# System Patterns

## Architecture

```
┌──────────────────────── Browser (static SPA) ──────────────────────────┐
│ React UI ── Zustand stores (scenario, playback, layers, live, ui)      │
│   ├─ MapLibre GL (OpenFreeMap vector tiles + AWS Terrarium DEM)        │
│   │    └─ deck.gl overlay (wavefronts, intensity, impact layers)       │
│   ├─ uPlot (waveforms)                                                 │
│   └─ Comlink ── Web Workers ── src/engine/ (pure TypeScript physics)   │
│                                                                        │
│ public/data/  prepared static datasets + manifest.json                 │
└─────────────────────────────────┬──────────────────────────────────────┘
                                  │ /api/*
                Cloudflare Worker `worker/` (stateless allowlist proxy + cache headers)
                → AFAD, Kandilli, KOERI FDSN (no CORS or no HTTPS upstream)
```

- No application server. The proxy only forwards allowlisted paths, sets cache headers and maps upstream failures to 502/504. Sources with CORS and HTTPS (USGS, EMSC, EIDA federator) are called directly.
- Cloudflare Workers static assets serve the SPA; `run_worker_first: ["/api/*"]` routes only API calls through the Worker.
- `@cloudflare/vite-plugin` runs the same Worker inside the Vite dev server (workerd), so `npm run dev` has the real proxy without a Cloudflare account.
- Python exists only in `pipeline/` for one-off data preparation by developers. Its outputs are committed to `public/data/`; viewers never run Python.

## Rules of the layout

- Source file names are kebab-case (`wave-front-layer.ts`, `map-view.tsx`). Exported React components are PascalCase. Memory bank files keep the Cline camelCase convention.
- Named exports only. Default exports only where a tool requires them (config files).
- One component per file. No barrel files except each feature's `index.ts`.
- Dependency direction: `app → features → (state, data, workers, components, lib, types)`; `workers → engine`; `engine → (lib/math, types)` only. Enforced by ESLint import boundaries.
- A feature never imports another feature's internals; it uses that feature's `index.ts`.
- Tests mirror the source path under `tests/<level>/`. No test files under `src/`, `worker/` or `pipeline/src/`.
- `src/app/` holds the shell: layouts per breakpoint (`desktop-layout`, `tablet-layout`, `phone-layout`), status bar, and `panels.ts`, the single registry of panel titles, icons and content used by every layout.
- Proxy logic in `worker/proxy.ts` uses only standard Fetch API types and receives `fetch`, cache and `waitUntil` as dependencies, so it is tested in Node; `worker/index.ts` is the only Cloudflare-specific file.
- The map feature exports `MapViewport`, which lazy-loads MapLibre and deck.gl so the shell paints first.
- New top-level folders, new features or new engine modules are recorded here before they are created.

## Key patterns

- **Compute once, scrub freely.** `engine/sim` turns a `Scenario` (including seed) into a `SimulationResult` of typed arrays indexed by grid cell and time step. Playback only reads; scrubbing never recomputes.
- **Single clock.** `state/playback` owns one global time `t` in seconds from origin. Every layer and panel derives its view from `t` through selectors.
- **Worker isolation.** Each heavy module runs in its own worker and is loaded lazily when its feature is first enabled. Results cross the boundary as transferable typed arrays.
- **Grid-first physics.** Arrival times, intensity and site terms live on one regional grid (about 1 km desktop, 2 km mobile). Wavefronts are isochrones of the arrival-time grid at time `t` (marching squares), which handles finite faults and layered media naturally.
- **Consistency between views.** Synthetic station records are scaled to the GMPE median at the station so map and telemetry never disagree.
- **Schema at every boundary.** External feeds, prepared assets and URL-shared scenarios are validated with zod before entering the app.
- **Determinism.** All randomness comes from `engine/random` seeded by the scenario.
- **Lazy data.** `manifest.json` lists assets; roads, cells and bathymetry load only when their module is enabled.

## Critical paths

1. Scenario → rupture discretization → arrival-time grid → GMPE grid → wavefront isochrones → map. This is the first vertical slice.
2. Arrival times → synthetic records → STA/LTA triggers → EEW alert → district countdowns.
3. Intensity → damage → road edge costs → corridors; intensity → cell tower load.
4. Fault slip → seafloor displacement (Okada) → shallow-water solver → coastal arrivals.
