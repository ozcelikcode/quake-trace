# System Patterns

## Architecture

```
┌──────────────────────── Browser (static SPA) ──────────────────────────┐
│ React UI ── Zustand stores (scenario, playback, layers, live, ui)      │
│   ├─ MapLibre GL (OpenFreeMap vector tiles + AWS Terrarium DEM)        │
│   │    └─ deck.gl overlay (wavefronts, intensity, impact layers)       │
│   ├─ uPlot (waveforms)                                                 │
│   └─ Comlink ── Web Workers ── src/engine/ (pure TypeScript physics)   │
│                                                                        │
│ public/data/  prepared static datasets + manifest.json                 │
└─────────────────────────────────┬──────────────────────────────────────┘
                                  │ /api/*
                Cloudflare Worker `worker/` (stateless allowlist proxy + cache headers)
                → AFAD, Kandilli, KOERI FDSN (no CORS or no HTTPS upstream)
```

- No application server. The proxy only forwards allowlisted paths, sets cache headers and maps upstream failures to 502/504. Sources with CORS and HTTPS (USGS, EMSC, EIDA federator) are called directly.
- Cloudflare Workers static assets serve the SPA; `run_worker_first: ["/api/*"]` routes only API calls through the Worker.
- `@cloudflare/vite-plugin` runs the same Worker inside the Vite dev server (workerd), so `npm run dev` has the real proxy without a Cloudflare account.
- Python exists only in `pipeline/` for one-off data preparation by developers. Its outputs are committed to `public/data/`; viewers never run Python.

## Rules of the layout

- Source file names are kebab-case (`wave-front-layer.ts`, `map-view.tsx`). Exported React components are PascalCase. Memory bank files keep the Cline camelCase convention.
- Named exports only. Default exports only where a tool requires them (config files).
- One component per file. No barrel files except each feature's `index.ts`.
- Dependency direction: `app → features → (state, data, workers, components, lib, types)`; `workers → engine`; `engine → (lib/math, types)` only. Enforced by ESLint import boundaries.
- A feature never imports another feature's internals; it uses that feature's `index.ts`.
- Tests mirror the source path under `tests/<level>/`. No test files under `src/`, `worker/` or `pipeline/src/`.
- `src/app/` holds the shell: layouts per breakpoint (`desktop-layout`, `tablet-layout`, `phone-layout`), status bar, and `panels.ts`, the single registry of panel titles, icons and content used by every layout.
- Proxy logic in `worker/proxy.ts` uses only standard Fetch API types and receives `fetch`, cache and `waitUntil` as dependencies, so it is tested in Node; `worker/index.ts` is the only Cloudflare-specific file.
- The map feature exports `MapViewport`, which lazy-loads MapLibre and deck.gl so the shell paints first.
- `src/data/` has no barrel: import `repository.ts`, `schemas.ts`, `grid.ts`, `use-dataset.ts` directly. `browser.ts` holds the app's single `DataRepository`; tests build their own with a disk fetcher.
- New top-level folders, new features or new engine modules are recorded here before they are created.

## Key patterns

- **Compute once, scrub freely.** `engine/sim` turns a `Scenario` (including seed) into a `SimulationResult` of typed arrays indexed by grid cell and time step. Playback only reads; scrubbing never recomputes.
- **Single clock.** `state/playback` owns one global time `t` in seconds from origin. Every layer and panel derives its view from `t` through selectors.
- **Worker isolation.** Each heavy module runs in its own worker and is loaded lazily when its feature is first enabled. Results cross the boundary as transferable typed arrays.
- **Grid-first physics.** Arrival times, intensity and site terms live on one regional grid (about 1 km desktop, 2 km mobile). Wavefronts are isochrones of the arrival-time grid at time `t` (marching squares), which handles finite faults and layered media naturally.
- **Consistency between views.** Synthetic station records are scaled to the GMPE median at the station so map and telemetry never disagree.
- **Schema at every boundary.** External feeds, prepared assets and URL-shared scenarios are validated with zod before entering the app.
- **Determinism.** All randomness comes from `engine/random` seeded by the scenario.
- **Lazy data.** `manifest.json` lists assets; roads, cells and bathymetry load only when their module is enabled.
- **Data repository.** `DataRepository` (src/data/repository.ts) fetches the manifest once and exposes typed, zod-validated loaders: `json(id)`, `grid(id)`, `roads()`, `cells()`. React reads them through TanStack Query hooks (`use-dataset.ts`) with infinite stale time. Binary datasets (`roads.bin`, `cells.bin`) are sectioned files described by the manifest `layout` and viewed without copying.
- **One grid convention across languages.** North-up, row-major float32 (row 0 = north). Python writes it (`grid.py`), TypeScript reads it (`grid.ts`); both are tested on the same real points (Fatih population, Çınarcık depth, Kadıköy district index).
- **Draped versus floating layers.** deck.gl layers are not draped on MapLibre terrain (they render at sea level and the terrain hides them). Static 2D context (districts, faults, stations, later infrastructure) uses MapLibre native GeoJSON layers, re-applied on every `style.load`. Dynamic rasters (intensity) use a MapLibre `image` source updated with `updateImage({ image: ImageData })`: with terrain, MapLibre caches draped rasters and only a source update invalidates that cache (a `canvas` source stays stale). Dynamic 3D geometry (wavefront curtains, rupture, epicentre) uses deck.gl, lifted onto the terrain with the elevation grid × terrain exaggeration.
- **Overlay order.** quakeTrace overlays go before the first label that follows the basemap's last line layer (`layer-order.ts`): above roads and boundaries, below place names. Intensity sits below the reference lines.
- **Frames outside React.** The map subscribes to the scenario and playback stores with `store.subscribe` and draws through `SimulationRenderer`; React renders only the panels, which select narrow slices (for example the number of districts reached, not the clock).
- **Simulation in a worker.** `src/workers/simulation.worker.ts` exposes `simulate` through Comlink and transfers the result arrays; `simulation-client.ts` starts the worker lazily. Features call it (`use-run-scenario.ts`), write `state/scenario-store.ts` and reset `state/playback-store.ts`.
- **Telemetry drawing.** Waveforms are canvases painted outside React by `useCanvasFrame` (resize, visibility, theme and clock subscriptions); records are reduced to 50 ms min/max envelopes with a running peak, and painters draw one stroke per device column up to the playback time, never beyond it. Readouts that change every frame (peak so far) are written to DOM nodes from the same paint. Station rows are in trigger order, so triggered stations are a prefix and React re-renders only when that count changes.
- **Focused station.** `state/telemetry-store.ts` holds the chosen station id; `resolveFocusedStation` (first trigger when none is chosen) is shared by the telemetry panel and the map ring, because features cannot import each other.
- **Map feature state.** Facilities are a MapLibre circle layer (`promoteId: 'id'`) whose colour comes from feature state written by `SimulationRenderer` only when a facility's state changes; states are reset on new results and style reloads.
- **Tsunami in its own worker.** `use-run-scenario.ts` starts `workers/tsunami.worker.ts` after the shaking result; `state/tsunami-store.ts` holds the result with a run token so a late result for an older scenario is dropped. When it arrives the playback store's `tsunami` extent is set and the scale becomes selectable; choosing it switches the map raster to the sea surface (map-view subscription).
- **Timeline scales.** `state/playback-store.ts` keeps one clock with per-scale extents (`TIMELINE_SCALES`: speeds, default speed, keyboard steps); `durationS` is the active scale's end.
- **Response layers.** Corridors, impaired roads and cell sites are scenario GeoJSON sources built by `response-layers.ts` from the result and the road graph (`SimulationRenderer.setRoads`); `TimedReveal` keeps items sorted by time and writes feature state only for items whose visibility changes. The road graph is loaded once by the scenario feature and the map (TanStack Query) and copied to the worker with each run (one 5.6 MB buffer).
- **Shared constants.** Facility kinds and the facility state thresholds live in `types/damage.ts`, because the engine (routing, network) and the UI (infra) use the same rule.
- **Shared types.** Types used by both the engine and the UI (`GridSpec`, `Scenario`, `SimulationResult`) live in `src/types/`, because features may not import the engine.

## Critical paths

1. Scenario → rupture discretization → arrival-time grid → GMPE grid → wavefront isochrones → map. This is the first vertical slice.
2. Arrival times → synthetic records → STA/LTA triggers → EEW alert → district countdowns.
3. Intensity → damage → road edge costs → corridors; intensity → cell tower load.
4. Fault slip → seafloor displacement (Okada) → shallow-water solver → coastal arrivals.
